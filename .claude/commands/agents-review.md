# エージェント構成レビュー

`.claude/agents/` のエージェント定義を見直し、改善案を提案・適用する。
作業完了後やエージェントの役割に重複・不足を感じたときに呼び出す。

## 手順

### 1. 現在のエージェント構成を把握する

`.claude/agents/` のファイルをすべて読み込み、各エージェントの以下を整理する：
- 名前・説明
- tools（権限の過不足がないか）
- model（コスト効率は適切か）
- 役割の重複・カバーできていない領域

### 2. 直近の作業傾向を分析する

CLAUDE.md の「エージェント改善履歴」と過去の作業内容から、以下を確認する：
- 頻繁に呼び出されているエージェントはどれか
- 呼び出されていないエージェントはあるか
- エージェントが担当範囲外の作業を行ったケースはあったか

### 3. 改善案をまとめる

以下の観点で改善案を提案する：

| 観点 | チェックポイント |
|-----|----------------|
| 役割 | 重複があれば統合、カバレッジ不足があれば新設を検討 |
| tools | 不足なら追加、不要なものは削除（最小権限原則） |
| model | 軽量タスクは `haiku`、複雑な判断は `inherit` または `sonnet` |
| description | Claude が自動委譲できるよう、発動条件が明確か |
| チームサイズ | 3〜5人のチームメイトで適切か（公式推奨） |

### 4. 変更を適用する（必要があれば）

改善が確実な場合は直接 `.claude/agents/` を更新する。
不確かな場合は改善案のみを提示し、ユーザーに判断を委ねる。

### 5. CLAUDE.md の「エージェント改善履歴」に記録する

```
- YYYY-MM-DD: <変更内容と理由>
```

## 判断基準

- **統合を検討**: 2つのエージェントが同じファイルを読み書きし、手順が重複している
- **新設を検討**: 同じ手順を 3 回以上エージェントなしで実行した
- **削除を検討**: 一度も呼び出されていないエージェントが 3 ヶ月以上経過
- **tools を絞る**: エージェントが実際に使っていない tool がある
