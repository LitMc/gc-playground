# gc-playground リポジトリ構成（なぜこうなっているか）

## 方針：学習と並行して進めるための “小さな独立プロジェクト” 集合
このリポジトリは、1つの巨大なファームウェアに全てを詰め込むのではなく、
「1テーマ = 1実験」単位で進めるために、examples/ 配下に小さなターゲットを複数持つ。

### ねらい
- 学習コストを局所化できる（PIO、DMA、プロトコル層、変換、計測…）
- 失敗や破壊的変更が他へ波及しにくい
- CIで “変更があったものだけ” をビルドする設計にも寄せやすい

## 主要なプロジェクト

| ディレクトリ | 概要 |
|---|---|
| `examples/measure` | 計測用ファームウェア。パッド⇔コンソール中継 + 固定パターン送信で S 変換の 256×256 LUT を収集する |
| `examples/bridge` | 入力補正ブリッジ。計測データから構築した P(s) = S⁻¹⁺(φ(C(s))) パイプラインでスティック入力をリアルタイム補正する |

## 追加ルール（推奨）
- 新しい実験は examples/<topic>/ を作り、単体でビルドできるようにする
- 共通化は「2回以上コピペしたら検討」くらいの温度感で行う
- docs/ に “その実験の目的・観測方法・期待出力” を短く残す
